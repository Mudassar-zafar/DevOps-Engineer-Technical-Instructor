Hatched blocks are the two breaks. Five hours in total.

  1. Recap and blockersOpen questions from last week's lab and the self-study.
  2. Concept firstThe architecture drawn and explained before anyone opens the console.
  3. Live buildThe instructor builds it live, mistakes included, so learners see real debugging.

Worked example: Week 5, AWS VPC

  • Concept. How traffic reaches a public subnet through the internet gateway, and how private instances reach out through a NAT gateway without being reachable from outside.
  • Live build. A two-tier VPC across two Availability Zones: public and private subnets, route tables, a NAT gateway, security groups and network ACLs.
  • Guided lab. Learners build the same VPC, then remove the private route to the NAT gateway on purpose and fix it.
A private instance cannot download updates. What do you check first?

The private subnet's route table: it needs a 0.0.0.0/0 route to the NAT gateway, and the NAT gateway must sit in a public subnet that routes to the internet gateway.

Security group or network ACL: which one is stateful?

The security group. Return traffic is allowed automatically. A network ACL is stateless, so return traffic needs its own rule.

Why spread across two Availability Zones?

If one zone has a problem, the other keeps serving. It is also the base for the load balancing and Auto Scaling work in Week 6.

Cost habit. The NAT gateway bills by the hour, so learners tear it down at the end of the lab.
Carry-over. In Week 7 the same VPC is rebuilt in Terraform, so learners code something they already understand.

What we check on every pull request

Terraform

  • Plan output attached to the PR
  • No hardcoded secrets
  • Variables and outputs used properly, remote state
  • Checkov findings fixed or explained

Pipelines

  • Stages fail fast
  • SonarQube quality gate enforced
  • Trivy scan before the image is pushed to Nexus
  • Credentials kept in Jenkins, not in code

Kubernetes and Helm

  • Resource requests and limits set
  • Readiness and liveness probes
  • No "latest" image tags
  • Separate values per environment

Docs

  • README covers how to run it and how to tear it down
  • A short note on what runs where and why

Where learners usually get stuck

  • Scalable image sharing web applicationLAMP on EC2, RDS, ELB, Auto Scaling, S3, CloudFront
    Watch for: uploads saved on the instance disk vanish when Auto Scaling replaces it. They belong in S3.
  • Containerised Java applicationJenkins, SonarQube, Nexus, Docker, Terraform, Ansible
    Watch for: Nexus registry login and Jenkins credentials, then the SonarQube gate failing the build.
  • Automated disaster recoverySeparate Auto Scaling groups, scheduled Ansible configuration
    Watch for: new instances must configure themselves. The only real test is terminating one and watching it recover.
  • Microservices on kubeadmHA control plane, HAProxy and Keepalived, bastion, Helm
    Watch for: the control plane behind HAProxy and Keepalived, and reaching private nodes through the bastion.
  • E-commerce microservicesKubernetes with ArgoCD and Istio
    Watch for: the namespace not labelled for Istio sidecar injection, and manual kubectl edits that ArgoCD quietly reverts.
